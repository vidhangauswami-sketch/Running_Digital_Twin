This trains a real model in your browser by gradient descent, so the loss curve below is genuine. The models are deliberately simple (ridge-linear or a 1-hidden-layer network) — good for quick site-level estimates, not a validated engineering simulator. For continuous targets, “accuracy” is reported as R² (1.0 = perfect, 0 = no better than the mean); RMSE/MAE are in the target’s original units.

Upload your own cleaning log and date-wise per-inverter generation and get the same before/after, soiling-loss, cleaning-log and EDA analysis as the reference dashboard — computed entirely in your browser from those two files. This build has no weather/GTI/PVsyst feed, so the "weather-adjusted" gain is approximated by normalizing each inverter against the fleet's daily mean that day (a standard soiling-analysis trick: irradiance and temperature swings hit every inverter on the same site about equally, so dividing them out isolates the cleaning/soiling effect).

How the metrics are computed

% Actual — plain before/after average change in kWh, no adjustment.

% Normalized — before/after change in each inverter's output relative to the fleet's mean that day. This is the closest proxy available to a true weather-adjusted cleaning effect without irradiance data.

Soiling % — how far the inverter's relative output had drifted below its own trailing 45-day peak, right before the clean.

Status — Wrong-timing if the normalized gain was negative, Sub-optimal if it was a small positive gain (<2%), otherwise Optimal.
